# Slip project notes

Standalone game. Not part of WordTrio.

## Design decisions
- 4×4 grid. Moves: slide a row or column by one with wraparound. 16 moves in total, each undone by its inverse.
- Win: the four rows spell the four target words in any order. Alternative spellings in `alts` also count.
- No marks while playing. Check (3 per puzzle) marks rows that currently spell a target word. Any move clears the marks. The third check ends the game as a loss if the grid is not solved; the final feedback stays on the board and the result dialog opens after 1.6 seconds.
- Hint: first move of a shortest solution from the current grid (search limit 10), respecting locks. Counted in the share text.
- Dragging: axis locks after 10px to the larger movement. Commit past 35% of a tile. One step per drag. A drag along a locked row is refused.
- Animation: FLIP style. After the new grid is drawn each tile starts one slot back and glides in. A ghost tile carries the wrapped letter out of the opposite end. Column slides with locked rows skip locked slots (offsets use the real row distance). Drag commits skip it, since the preview already moved the line.
- Shortest path replay: available once S.over. Uses puzzle.solution via Core.pathStates. render(grid, true) draws replay frames with no locks and disabled arrows and never writes to S or storage.
- Puzzles are built from the solved grid by random slides (4, 5, 6 or 7 slides in rotation), so they are always solvable. Par is found by a two-ended search and verified again in test.js. Par range 3 to 7. A start with a correct row is rejected.
- Saved state is keyed by date and puzzle id. A mismatch or changed letters discards it. Storage keys: slip:state, slip:stats, slip:settings.

## Easy mode (setting, off by default)
- After a Check, correct rows lock (S.locks, sorted row indexes), at most Core.MAX_LOCKS = 2.
- Locked row: row moves are invalid (Core.validMoves excludes them). A column slide cycles only the free rows (Core.applyMoveLocked).
- Why the cap is 2: the group generated by the free-row moves was checked with sympy. Free rows of 4, 3 or 2 give the full symmetric group on the free cells (order 16!, 12!, 8!), so every arrangement is reachable. One free row gives only 4 rotations. test.js repeats the 2-row case by exhaustive search (40,320 states) and the 1-row case (4 states).
- S.lockPoints records S.moves.length at each lock event. Undo is allowed only past the last lock point.
- Reset clears locks and moves, not checks. Turning the setting off clears locks.
- Load validation drops locks if more than two, any index out of range, or any locked row is not currently a correct row.
- Core.minMoves(start, words, limit, alts, locks) searches with only valid moves and treats locked rows as fixed. It returns null if a locked row is not a target word.
- Share text gets 🔒easy if any lock was used (S.easyUsed).
- Par stays the unlocked par. A locked game can need more moves.
